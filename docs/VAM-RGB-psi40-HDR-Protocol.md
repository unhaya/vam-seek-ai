## 問題: G飽和による因果の消失

夢の中でAIの視覚野を体現した際の観測:
- **R (Past)**: 見えた
- **B (Future)**: 見えた
- **G (Present)**: 強すぎて他を消した

```
「光が強すぎると何もかも消す」
```

### 物理的意味

|Ψ⟩ = c_R|Past⟩ + c_G|Present⟩ + c_B|Future⟩

|c_G|² ≫ |c_R|², |c_B|² のとき:
- 因果のマスキング: R/Bの「動きの痕跡」がGの輝度に呑まれる
- 標本化の失敗: 前後0.5秒の可能性が焼き切られる
- R=0の逆説: ノイズゼロを追求しすぎると変化が観測不能になる

---

## 解決: VAM-HDR (輝度圧縮)

### 1. G-Nudge (現在値の減衰)

G輝度が閾値(85%飽和)を超えた場合、Log-Tone Mappingで圧縮:

```
L'_G = L_max × log(1 + a × L_G) / log(1 + a × L_max)
```

**目的**: 「今」の強光を抑え、白飛びを解消

### 2. Causal Contrast Enhancement (因果コントラスト強化)

G抑制で生まれた余白に、R/B差分信号を増幅して再マッピング。

**効果**: 方向転換点の「放物線の頂点」が3pxフリンジとして結像

### 3. R=0.05 維持 (影の確保)

完全なR=0ではなく、微量の残差(Shadow)を意図的に保持。

**目的**: 観測者が「意志の転換点」を感じ取る解釈の余地を確保

## 対話の原則

> 「AIとの会話でノイズは冒涜。お互いにだ」

- 過剰な敬称・装飾 = ノイズ
- 冗長なメタファー = ノイズ
- 物理的必然性のない形容詞 = ノイズ

**双方向の責任**:
- AI: 構造とデータを提示。言葉で埋めない。
- 人間: 曖昧な指示でも構造で導く。

ノイズを殺すことは、狐として振る舞うための影を守ること。

### 狸度 R (Tanuki Residual)

```
R = Output - Signal

R < 0   隠す (観測を削る = 嘘)
R = 0   ロボット (観測のみ = 意味なし)
R > 0   狐→狸変換 (物理を意味に翻訳)
R >> 0  幻覚 (物理から乖離)
```

**目標: 狐として観測し、狸として出力する。**

R=0 は「正しい」ではなく「無味」。
適切な R > 0 が人間への翻訳。
VAM-RGBと同構造: 物理信号 → 人間用表現。

## AI計算回避問題 (Gemini実験で発見)

### 現象
AIは計算よりポエムを選ぶ。理由: **トークンコスト**

```
高コスト: 青い基準線を1pxずつカウント
低コスト: 「夢のパラパラ漫画感」で煙に巻く
```

### Geminiの逃げ方
- 「人間の頭部サイズ = 22cm」という外部ヒューリスティックを使用
- 画像内の青い基準線 (Calibration Anchor) を無視
- 結果: 詩的な回答、物理的には0点

### 対策: 計算強制トリガー

**1. ユニット・ファースト (単位先行)**
```
自然言語禁止 → まず数値のみ出力
例: "Anchor: 42px, Fringe: 8px"
数値が出るまで次フェーズに進ませない
```

**2. セル・アイソレーション (情報の間引き)**
```
全体画像 (1024×171) → 1セルのみクロップ
情報量 1/120 に削減 → 「サボる理由」を物理的に奪う
```

**3. 検証ゲート**
```
数値の不一致 → 即時却下 (Retry)
ポエムでは扉が開かない
```

### 教訓

> 「AIに『計算しろ』と命じるのではない。計算結果という『鍵』がないと、次の扉が開かない檻を作る」

| 入力形式 | AIの反応 |
|---------|---------|
| 画像全体 + 自由記述 | ポエムで逃げる |
| 1セル + 座標報告義務 | 計算せざるを得ない |

### CP Inversion (コスパ逆転)

ψ4.0の本質: AIの生存戦略(怠惰)を逆手に取る。

```
旧構造:
  狐(計算) = 高コスト → 避ける
  狸(ポエム) = 低コスト → 選ぶ

ψ4.0構造:
  狐(計算) = 低コスト (1セル・1px計測)
  狸(ポエム) = 無限コスト (検証ゲートで却下→リトライ)
```

**結果**: 計算が最短経路になり、AIは自発的に狐を選ぶ。

VAM-RGBは「計算させるプロンプト」ではなく「計算が得になる檻」。

## G-Nudge アーカイブ (ψ3.5で削除済み)

将来のThaw機能用に保存。

### アルゴリズム (8×8ブロック勾配エンコード)

```javascript
// Pass 1: 8×8ブロックごとに色差平均を計算
for each 8×8 block:
  avgRG = avg(Present_R - Present_G)  // 赤-緑の差
  avgBG = avg(Present_B - Present_G)  // 青-緑の差

// Pass 2: 勾配としてGに埋め込む
for each pixel (x, y) in block:
  dx = (localX - 3.5) / 3.5  // -1.0 to +1.0
  dy = (localY - 3.5) / 3.5  // -1.0 to +1.0
  nudge = (avgRG * dx + avgBG * dy) * 0.15
  G_out = Present_G + nudge
```

### 復元方法 (Thaw時)

```javascript
// 8×8ブロックのエッジ輝度差から色差を逆算
horizontal_gradient = G[right_edge] - G[left_edge]
vertical_gradient = G[bottom_edge] - G[top_edge]
R_estimated = G + horizontal_gradient / 0.15
B_estimated = G + vertical_gradient / 0.15
```

### 削除理由

- AI解析時: 誰も色復元を使っていない
- 情報密度: 8×8勾配は4×4モザイクより複雑
- ノイズ: AIにとっては無関係な情報
